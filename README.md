Test for GD3 Rhythm Game

General lessons/notes from this project:
1. Precision is important. Every marker in the song has to be spot on, and detection needs to not only be precise to the song, but have understanding of input lag.
2. Indicators are super important as well. Predicting future notes can be somewhat difficult especially on your first listen.
3. Sound design needs to be spot on. I knew this going into it but if the rhythm game is to be built on a larger scale both the music and sound effects need to be really accurate.
4. It's difficult to maintain movement, aim, and timing. Their either needs to be ways to make it more forgiving for the player, or understand the kind of difficulty being made.
5. Level design is also very important. There is a very thin line between claustrophobic and too open (especially if dashes, grappling hooks, wall jumps, and other movement abilities are to be added).
6. Visual clarity is also important. Visual elements need to be both clear and easy to find, there is going to be too much going on to also worry about 12 different UI elements.
7. Visual elements also have to be very clean and consistent (similar issue as visual clarity).
8. Timing. Similar to difficulty this game is all about flow, so it has to be very forgiving to keep momentum going.
9. Enemy spawning is going to be rather challenging since the player is to be constantly moving while also killing enemies (levels may have to be cyclical or similar to a large deathmatch level).
10. Pacing. While the player is expected to constantly move, there needs to be moments to breathe. If the player is constantly overwhelmed it's going to not be fun.
